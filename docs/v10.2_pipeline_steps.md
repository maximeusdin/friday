# V10.2 Pipeline — Every Step

This document describes **every step** of the current V10.2 agentic-first pipeline from user query to final answer.

---

## Entry point

- **`run_v10_query(conn, question, scope, ...)`** in `retrieval/agent/v10_runner.py`
- Called by the CLI / API with the user’s natural-language question and optional scope (collections).
- When **V10_AGENTIC_FIRST=1** (default), only **Stage A** and **Stage D** run; Stages B and C are skipped.

---

## Stage A: Query interpretation

**Goal:** Turn the raw question into a structured span lattice and a lexicon of entities/aliases the rest of the pipeline will use.

### A.1 — Span lattice (deterministic)

- **`spot_query_spans_v10(conn, question, scope_hint=scope_collections)`** in `v10_spans.py`
  1. **Tokenise** the query (word tokens, including Cyrillic/apostrophe/hyphen).
  2. **Generate n-grams** for n=1..5 from those tokens (contiguous substrings with character offsets).
  3. For each n-gram:
     - **Normalise** with shared normaliser (casefold, possessive strip, etc.) → `norm_key`.
     - Skip if stopword-only (single-token).
     - **Look up candidates:**
       - Exact **canonical name** (entities table).
       - Exact **alias** (entity_aliases).
       - **Fuzzy** canonical/alias (if key length ≥ 5, not stopword) via pg_trgm.
       - **Short-token PEM candidates** (≤4 chars): if PEM is available and scope includes alias collections, query **page_entity_mentions** (scope-aware) for candidate entities.
       - **Synthesised fullname** for multi-word spans (first + last name match on person entities).
     - Attach **prior counts** from alias_lexicon_index and PEM when available.
     - Set **surface_kind**, **valid_collections**, **collision**, **resolution_status** (resolved/ambiguous/unresolved), **span_kind**.
  4. Emit spans that have candidates **or** are “referent-likely” (e.g. multi-word phrase, hyphen/apostrophe).
  5. Compute **overlaps** and **dominates** between spans.
  6. **Prune** to `MAX_SPANS` (40), keep best by resolution status, length, number of candidates; recompute overlaps/dominates on the kept set.

- **Output:** `SpanLatticeV10` (query + list of `SpanEntry`: span_id, text, start, end, norm_key, candidates, overlaps, dominates, etc.).

### A.2 — LLM span selection

- Lattice is serialised to JSON and sent to the LLM with **V10_SPAN_SELECTION_PROMPT**.
- **Schema:** `chosen_span_ids`, `suppressed_span_ids`, `entity_hypotheses`, `alias_spans` (with `activate_alias_resolution`).
- **Parse** response into `SpanSelection`; on parse failure, fall back to choosing all non-dominated spans.

### A.3 — Lexicon and plan

- **`build_lexicon_from_lattice(conn, lattice, selection)`** in `v10_lexicon.py`
  - Builds **LexiconV10**: `entities_in_play`, `aliases_by_entity_scoped`, `entities_by_alias_scoped`, etc., from the **chosen** spans and their candidates.
- **`_check_and_sync_index_revision(conn, lexicon)`**
  - Syncs PEM index revision; clears stale alias permissions if revision changed.
- **`load_referent_rules_into_lexicon(conn, lexicon, alias_doc_keys)`** if any alias doc keys (currently none at Stage A).
- For each chosen span that is **resolved** (single candidate): **`lexicon.set_resolved_referent(...)`** with status `"confirmed"`.
- **`ResolutionPlanV10`** is built: selected spans, span_selection, entity_hypotheses.

### A.4 — Agentic-first branch (no B/C)

- If **V10_AGENTIC_FIRST**:
  - **Backfill alias namespaces** for all entities in the lexicon: **`backfill_alias_namespace(conn, lexicon, initial_entity_ids)`**.
  - **Initial recommended boosts:** **`_compute_recommended_boosts(lexicon, conn, set())`** (entity forms + any alias backlinks for Venona/Vassiliev).
  - **Lattice summary for LLM:** **`_build_lattice_summary_json(lattice, selection, lexicon)`** (structured summary of chosen spans, candidates, boosts).
  - Then go straight to **Stage D** with that summary and initial boosts; **all_hits** and **all_mentions** are still empty (no pre-run retrieval).

---

## Stage D: LLM-driven investigation loop

**Goal:** The LLM drives all retrieval via tools, then produces a final synthesis (narrative + claims) that is verified.

### D.1 — Initial message setup

- **System:** `V10_SYSTEM_PROMPT` (identity-aware pipeline, mention-index usage, alias power, extraction reframe, tool reference, etc.).
- **User [1]:** Investigation framing:
  - Question.
  - **Span Lattice Summary** (JSON) — “use these as your starting anchor”.
  - **Initial Recommended Boosts** (JSON) — “use these in your first search_v10 call”.
  - Instructions: (1) Start with initial boosts, (2) Review enrichment after each search, (3) Use recommended_boosts for follow-ups, (4) Call **fetch_chunks** when you have relevant chunk_ids, (5) Set **final=true** to synthesize with cited claims, (6) Verification and retries.
- **Assistant [2]:** Current Lexicon State (JSON + short text) — overwritten each round after a search.
- **Assistant [3]:** Strategy Hint (explore/exploit or stall nudge) — overwritten each round when controller is used.

### D.2 — Loop (up to V10_MAX_TOOL_CALLS rounds)

- **`for round_num in range(V10_MAX_TOOL_CALLS)`** with **`tool_calls_remaining`** (starts at 30).
- Each iteration:
  1. **Call LLM** with `V10_RESPONSE_FORMAT` (strict JSON: `final`, `scratchpad_update`, `synthesis`) and **V10_TOOLS_DEF** (search_v10, fetch_chunks, extract_mentions, resolve_referent_v10, alias_index_summary_v10, alias_index_lookup_v10, aliases_for_entity_v10, alias_index_sample_v10, grant_alias_power_v10, surface_top_referent_v10).
  2. **If the message has tool_calls:**
     - Append assistant message (with content and tool_calls) to `messages`.
     - For each tool call:
       - Decrement **tool_calls_remaining**.
       - Enforce **per-round search budget:** at most **MAX_SEARCHES_PER_ROUND** (3) `search_v10` calls per round; excess returns an error and skips that call.
       - **Controller mode** (if v10_policy available): compute gaps, choose explore/exploit, pass to enrichment.
       - **Execute tool:** **`_execute_tool(conn, tool_name, tool_args, lexicon, all_hits, all_mentions, chunks_fetched, scope, verbose, client=..., surfaces_cache=..., seen_doc_ids=..., controller_mode=...)`**.
     - **If any tool was search_v10:**
       - **Post-search enrichment:** **`enrich_hits_with_mentions(...)`** on the **new** hits from this round:
         - Batch-fetch full text for hits with short snippets.
         - Select alias-scoped vs other hits; apply per-doc cap (unless exploit).
         - For each selected hit not already in `all_mentions`: **`extract_mentions_dispatched(...)`** (LLM for alias-scoped when mode=llm, else deterministic; best-effort, no fallback control flow).
         - **`update_from_mentions(conn, lexicon, cm)`** per chunk.
         - **`backfill_alias_namespace(conn, lexicon, new_entity_ids)`** for newly seen entities.
       - **Update lexicon briefing** in `messages[LEXICON_MSG_IDX]`.
       - **Update strategy hint** in `messages[STRATEGY_MSG_IDX]` (explore/exploit or “stalled” nudge).
     - Append each tool result as a **tool** message; append to **trace**.
     - **Continue** to next loop iteration (next LLM call with tool results).
  3. **If the message has no tool_calls:**
     - **If msg.content is non-empty:**
       - Parse JSON. If **final** is true:
         - Read **synthesis.answer** → **narrative**, **synthesis.claims** → build **claims** (GroundedClaim with V9Claim + citation_chunk_ids).
         - **Verification:** **`_verify_claims(conn, claims, lexicon, all_mentions, verbose)`** (citation chunk_ids in all_mentions, linked entity_ids in lexicon). If not ok and retries left: append error message and call LLM again up to **MAX_VERIFY_RETRIES** (2); on success set **verification_ok** and break.
         - **Break** out of loop (return narrative, claims, trace).
       - If **final** is false: append assistant content and a “Continue your investigation…” user message; **continue** loop.
     - **If msg.content is empty** (no content, no tool calls):
       - **Empty-content nudge:** if **empty_content_nudges** ≤ 1 and **tool_calls_remaining** > 0: append assistant “(no content)” and a user nudge (“You must either use fetch_chunks then set final=true, or run more tools then synthesize…”); **continue** once. Otherwise **break**.
  4. If we **break** without narrative/claims: set **fallback narrative** (“No synthesis was produced… Try rephrasing or /deeper.”).

### D.3 — Tool execution (summary)

- **search_v10:** Parse/validate entity_boosts and alias_boosts (permission gating, lock validation); **search_chunks_v10**; append hits to **all_hits**; run **enrich_hits_with_mentions**; ** _compute_recommended_boosts**; return results + enrichment + recommended_boosts (+ warnings).
- **fetch_chunks:** Batch-load chunk text; store in **chunks_fetched**; return full text per chunk.
- **extract_mentions:** **extract_mentions_dispatched** for given chunk_id (using text from chunks_fetched or snippet); store in **all_mentions**; **update_from_mentions**; return structured mentions.
- **resolve_referent_v10,** **alias_index_summary_v10,** **alias_index_lookup_v10,** **aliases_for_entity_v10,** **alias_index_sample_v10,** **grant_alias_power_v10,** **surface_top_referent_v10:** Implemented in **v10_tools.py**; read from **page_entity_mentions** (mention index) with fallbacks; return surface_raw, surface_norm_used, effective_collections, index_revision_used where applicable; **grant_alias_power** updates **lexicon** permissions.

### D.4 — After the loop

- **narrative** and **claims** (and **trace**) are returned from **`_run_synthesis`**.
- If narrative was still empty and no claims, the fallback narrative is already set inside **`_run_synthesis`**.

---

## After Stage D (in run_v10_query)

- **Result:** **V10Result** is filled: **narrative**, **claims**, **lattice**, **lexicon**, **plan**, **chunk_mentions** (all_mentions), **chunks_fetched**, **investigation_trace**, **unresolved_aliases** (from lexicon alias_mapping_hypotheses with status unresolved/ambiguous).
- **Index revision** is not updated again here (PEM revision is set by the populate script).
- Optional **progress_callback** and **verbose** output (“Narrative length: …, Claims: …”).

---

## Summary flow (agentic-first)

1. **Stage A:** Query → span lattice (PEM-aware, scope-aware) → LLM span selection → lexicon + plan; backfill aliases; initial boosts; lattice summary.
2. **Stage D:** Initial prompt (question + lattice + boosts + instructions). Loop: LLM → tool calls (search, mention-index, fetch_chunks, etc.) → execute tools → on search: enrich hits (extract mentions, update lexicon, backfill) and update lexicon/strategy in messages → LLM again. When LLM returns **final=true** with synthesis → verify claims → return narrative + claims. If LLM returns empty content → nudge once, then fallback narrative if still no answer.
3. **Result:** V10Result with narrative, claims, lexicon, trace, unresolved aliases, chunks_fetched, chunk_mentions.

---

## Constants

- **V10_MAX_TOOL_CALLS:** 30 (max rounds / total tool-call budget).
- **MAX_SEARCHES_PER_ROUND:** 3.
- **MAX_VERIFY_RETRIES:** 2 (verification retries after failed grounding).
- **MAX_SPANS:** 40 (lattice size after pruning).
- **ALIAS_SCOPED_COLLECTIONS:** venona, vassiliev (where codenames/alias tools are meaningful).
